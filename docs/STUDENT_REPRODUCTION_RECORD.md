# 케셰브 22단계 새 환경 재현 기록 — 진행 중

이 기록은 **학생이 제공한 터미널 출력과 저장소 원문의 정적 확인**을 구분합니다. 이 문서 작성 과정에서 저장소를 복제하거나 서버·브라우저를 실행하지 않았습니다. 아래 `기준 커밋`은 재현 기록을 만들기 전에 사용자가 터미널에서 확인해 제공한 커밋이며, 이 문서가 포함될 최종 커밋이나 재현 완료 증거가 아닙니다.

## 1. 제출 대상과 기준 커밋

| 항목 | 값 | 근거·상태 |
|---|---|---|
| 저장소 URL | `https://github.com/Andy255319/on-client.git` | 사용자가 제공한 `git remote get-url origin` 출력. 저장소 공개 여부나 원격 접근 가능 여부는 확인하지 않음 |
| 브랜치 | `master` | 사용자가 제공한 `git branch --show-current` 출력 |
| 기준 커밋 | `37a7e061c2992d4ef888c5f9c41a32bf65eb73a6` | 사용자가 제공한 `git rev-parse HEAD` 출력. 40자리 값 |
| Git 최상위 폴더 | `on-client` | 제공된 `git rev-parse --show-toplevel` 출력의 마지막 경로 구성요소 |
| 원래 작업 폴더 상태 | 출력 시점에 변경 없음 | 제공된 `git status --short`가 비어 있었음. 이 문서 추가 이후의 작업 트리 상태는 확인하지 않음 |
| 제출·릴리스 커밋 | 미확인 | 이 기록과 최종 문서가 포함될 커밋은 아직 만들어지거나 확인되지 않음 |

위 정보는 사용자가 실행해 전달한 결과입니다. 이 도구가 Git 저장소 상태나 원격 저장소를 직접 조회한 것은 아닙니다.

## 2. 새 폴더에서 재현하는 절차

원래 폴더를 유지하고, 아래 명령은 **원래 저장소의 Git 최상위 폴더에서 새 PowerShell 창을 열어** 실행합니다. 새 폴더가 이미 있으면 명령은 중단되어야 하며, 기존 폴더를 지우거나 덮어쓰지 않습니다. 로컬 저장소를 복제하므로 해당 커밋이 GitHub에 아직 올라가지 않은 경우에도 원래 저장소에 커밋 객체가 있으면 사용할 수 있습니다.

```powershell
$source = (git rev-parse --show-toplevel).Trim()
if ($LASTEXITCODE -ne 0) { throw '원래 Git 저장소 최상위 폴더를 확인하지 못했습니다.' }
$target = Join-Path (Split-Path $source -Parent) 'on-client-repro-37a7e061'
if (Test-Path -LiteralPath $target) { throw '재현 폴더가 이미 있습니다. 내용을 확인하고 다른 새 폴더를 선택하세요.' }
git clone --no-checkout $source $target
if ($LASTEXITCODE -ne 0) { throw '별도 폴더 복제에 실패했습니다. 원래 작업 폴더는 변경하지 마세요.' }
git -C $target checkout --detach 37a7e061c2992d4ef888c5f9c41a32bf65eb73a6
if ($LASTEXITCODE -ne 0) { throw '요청한 커밋을 새 폴더에서 확인하지 못했습니다.' }
git -C $target rev-parse HEAD
git -C $target status --short
```

`rev-parse HEAD`가 위 기준 커밋과 정확히 같고 `status --short`가 비어 있는지 확인한 뒤에만 재현을 진행합니다. 이 복제는 **커밋된 파일만** 가져오며, 원래 폴더의 미커밋 파일이나 비밀 설정을 백업하지 않습니다. 복제 결과가 다르면 실행을 중단하고 원래 폴더를 보존합니다.

새 복제 폴더에서 다음을 순서대로 수행하고 실제 관찰값을 아래 실행 기록에 추가합니다.

1. `node --version`으로 설치된 Node.js 버전을 기록합니다. 저장소 기준은 `package.json`의 `24.19.0`; 실행 스크립트 허용 범위는 주 버전 22~24입니다. 실제 설치 버전은 아직 미확인입니다.
2. 이 프로젝트에 외부 npm 의존성 목록이나 `package-lock.json`은 확인되지 않았습니다. 기본 실행에는 `npm install`을 요구하지 않습니다. 확인하지 않은 설치 명령을 추가하지 않습니다.
3. 새 복제 폴더의 루트에서 다음을 실행합니다.

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
   ```

4. 스크립트가 안내하는 `http://127.0.0.1:5189/` 주소를 브라우저에서 열고, 서버 시작 문구와 화면을 실제로 확인해 기록합니다. HTTP 응답 및 화면 기동은 외부 계정·SDP/XDR·AI·OSV 연결 성공 증거가 아닙니다.
5. 실행 창에서 `Ctrl+C`로 종료하고, 같은 폴더에서 다시 시작해 브라우저가 다시 열리는지 확인합니다. 이 과정에서 기존 작업 폴더를 변경하거나 인증·설정 파일을 복사하지 않습니다.

## 5. 데이터 보존·백업·복원 계획과 제한

- **원래 작업 폴더:** 새 환경 재현은 별도 폴더에서 합니다. 원래 폴더를 삭제·초기화·체크아웃으로 덮어쓰지 않습니다. Git 복제는 커밋된 내용만 보존하므로 먼저 `git status --short`로 미커밋 작업을 확인합니다.
- **소스·문서:** 변경을 커밋 단위로 보존하고, 복원은 확인된 커밋을 별도 폴더에 체크아웃해 비교합니다. 이번 기록 작성 시 백업·복원은 수행하지 않았습니다.
- **인증·설정:** 운영자가 별도로 제공하는 인증서·자격·설정 파일은 저장소와 제출물 밖에 둡니다. 새 폴더에 원래 폴더의 비밀 설정을 무작정 복사하지 않습니다. 파일 내용이나 자격 증명을 문서화하지 않습니다.
- **보안 기록·접근 판정:** 연결된 엔진이 제공하는 기록은 해당 원천의 데이터입니다. 이 앱을 복제하는 것만으로 원천 기록을 백업하거나 복원하지 않습니다. 보존·복원은 원천 시스템 담당자의 승인 절차에 따릅니다.
- **선택적 조치 이력:** `src/actions/store.mjs`와 `src/actions/README.md`는 명시적으로 준비된 기존 SQLite DB에 조치 이력 테이블을 추가하는 경로를 설명합니다. 새 DB를 자동 생성하지 않고 이력 테이블에 변경·삭제 방지 제약이 있습니다. 해당 경로가 실제로 구성되었는지는 미확인입니다. DB 백업·복원은 DB 소유자의 승인된 절차로 수행해야 하며, 오래된 DB 스냅샷을 운영 원본에 덮어쓰거나 이력 테이블을 삭제하지 않습니다.
- **제한:** 이 저장소만으로 외부 원천 데이터나 운영 자격을 복구할 수 없습니다. 별도 백업 매체, 실제 백업 시각, 복원 시험 결과는 제공되지 않았으며 모두 미확인입니다.

## 6. 남은 확인과 버전 상태

현재는 **검증 중인 버전**입니다. 실제 집행 연결은 미완료이고, 새 환경 실행·브라우저·종료 후 재실행·13~21단계 확인은 수행되지 않았습니다. 이 기록은 학생 진술을 남기는 문서이며, 서버가 새 환경에서 실행했거나 실제 운영 연결을 검증했다는 뜻이 아닙니다. 22단계 원문 검토 결과도 실제 운영 인증이나 `v1.0` 자동 인증이 아닙니다.

현재 받은 정보에는 기준 커밋이 있지만, 이 실행 기록을 포함할 최종 커밋은 아직 없습니다. 같은 커밋에 실행 기록을 포함하라는 안내와, 문서 안에 그 최종 커밋 해시를 기록하라는 요구를 동시에 적용하면 문서 내용 변경으로 커밋 해시가 달라지는 순환 문제가 있습니다. 최종 기록을 작성하기 전에 과제 담당자가 재현 대상 커밋과 기록 포함 커밋의 관계를 어떻게 표기할지 확인해야 합니다. 임의로 해결 방식을 정하거나 이 기준 커밋을 최종 릴리스 커밋이라고 부르지 않습니다.
