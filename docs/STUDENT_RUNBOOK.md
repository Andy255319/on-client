# 케셰브 학생용 실행 설명서

이 문서는 이 저장소의 앱 루트를 찾아 실행하고, 코드 경계와 아직 확인하지 않은 범위를 구분하기 위한 안내입니다. **코드를 읽어 확인한 사실과 실제 PC에서 실행해 확인한 결과는 다릅니다.** 이 문서 작성 시 PowerShell 실행, 브라우저 확인, 외부 시스템 연결, 실제 OSV 조회는 수행하지 않았습니다.

## 1. 프로그램과 버전

| 항목 | 저장소에서 확인한 기준 | 이번 세션에서 실제 확인한 값 |
|---|---|---|
| 운영체제 | 실행 도구가 Windows PowerShell용 `.ps1` 파일로 제공됩니다. | 실제 PC의 Windows 버전은 확인하지 않았습니다. |
| Node.js | `package.json`의 `engines.node`는 `24.19.0`입니다. 실행 스크립트는 주 버전 22~24를 허용하고 `24.19.0`을 권장합니다. | 설치된 버전은 확인하지 않았습니다. PowerShell에서 `node --version`으로 확인하세요. |
| 앱 패키지 버전 | `package.json`의 `version`은 `0.2.11`입니다. | 이 값은 저장소 원문에서 읽은 값이며 실행 검증은 하지 않았습니다. |
| 서버 응답 버전 필드 | 서버 응답의 `starterVersion`은 `0.1.0`으로 별도 기록됩니다. 이는 앱 패키지 버전이나 제출 커밋을 뜻하지 않습니다. | 실제 화면·도움정보에서 표시되는 방식은 확인하지 않았습니다. |
| npm 패키지 | `package.json`에 외부 npm 의존성 목록이 없습니다. 이 저장소 파일 목록에는 `package-lock.json`이 없습니다. | 설치 명령이나 의존성 설치를 실행하지 않았습니다. 일반 실행에 `npm install`은 필요하지 않습니다. |
| 앱 주소 | 기본 주소는 `http://127.0.0.1:5189/`입니다. | 서버를 실행하거나 브라우저에서 열지 않았습니다. |

`package.json`의 앱 패키지 버전 `0.2.11`과 서버 응답 필드 `starterVersion: 0.1.0`은 서로 다른 이름과 용도의 버전 표기입니다. 화면 또는 도움정보에서 `starterVersion`이 보이면 서버가 보고한 시작 틀 메타데이터로 읽고, 앱 패키지 버전은 `package.json`에서 확인합니다. 두 값을 같다고 보거나 어느 하나로 현재 제출 커밋을 추정하지 않습니다.

> `package.json`의 버전 지정과 실행 도구의 허용 범위는 같은 표현이 아닙니다. 수업 기준은 Node.js `24.19.0`이며, 실행 도구는 Node.js 22~24를 허용합니다. 설치된 버전이 실제로 적합한지는 본인 PC에서 확인하세요.

## 2. 폴더 구조와 PowerShell을 여는 위치

다음 파일과 폴더가 함께 있는 **앱 루트**에서 실행합니다. 이 저장소에서는 앱 루트가 `on-client` 폴더에 해당합니다. 개인 PC의 절대 경로는 환경마다 다르므로 문서에 임의의 경로를 지정하지 않습니다.

```text
on-client/                         앱 루트 — 아래 명령을 실행할 위치
├── package.json
├── tools/
│   └── start-alekov.ps1
├── src/
│   ├── server.mjs
│   ├── engine.mjs
│   ├── ai/
│   └── vulnerabilities/
├── public/
│   ├── index.html
│   ├── app.js
│   └── vulnerabilities-view.mjs
├── student/
│   ├── extension.mjs
│   └── engine-adapter.mjs
└── docs/
    └── STUDENT_RUNBOOK.md
```

파일 탐색기에서 `on-client` 폴더를 연 뒤 주소 표시줄에 `powershell`을 입력하고 Enter를 누르면 그 위치에서 PowerShell을 열 수 있습니다. 이때 현재 위치가 `package.json`과 `tools`가 있는 폴더인지 확인하세요. Git 저장소 최상위가 `on-client`의 상위 폴더인 프로젝트에서는 **앱 실행 위치와 커밋 위치가 다를 수 있습니다.** 커밋할 때는 실제 Git 최상위 폴더를 사용하고 기존 작업을 먼저 확인하세요.

## 3. 실행·정상 시작·종료·재실행

### 기본 실행

앱 루트의 PowerShell에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\\tools\\start-alekov.ps1
```

실행 도구가 Node.js 버전, 필수 파일과 포트 사용 여부를 확인한 뒤 로컬 Node 서버를 시작합니다. 준비되면 다음과 같은 시작 안내가 표시되어야 합니다.

```text
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
```

그다음 브라우저에서 **http://127.0.0.1:5189/** 를 엽니다. 스크립트가 확인하는 정상 시작 신호는 로컬 주소의 HTTP 200 응답입니다. 이는 서버가 응답했다는 확인일 뿐, 계정 연결·SDP/XDR 연결·AI 권한·모델 응답이 성공했다는 뜻은 아닙니다.

### 선택 실행

예제 화면만 볼 때는 앱 루트에서 다음을 실행합니다. `-Demo`는 실제 회사 시스템 연결이나 연결 성취가 아닙니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\\tools\\start-alekov.ps1 -Demo
```

기본 포트가 이미 사용 중이면 다른 포트를 지정하고 브라우저 주소에도 같은 포트 번호를 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\\tools\\start-alekov.ps1 -Port 5190
```

주소 예: `http://127.0.0.1:5190/`

`package.json`의 대안 명령은 `npm start`와 `npm run demo`입니다. 실행 도구가 없는 구버전에서 `npm start`를 쓰는 경우 기본 주소는 `http://127.0.0.1:5189/`입니다. `npm run check`는 `student/extension.mjs`의 Node.js 문법만 검사하며 브라우저 동작이나 과제 통과를 확인하지 않습니다.

### 종료하고 다시 실행

- 기본 실행은 서버를 시작한 PowerShell 창에서 **Ctrl+C**를 눌러 종료합니다.
- 다시 실행할 때는 같은 앱 루트에서 기본 실행 명령을 다시 입력합니다.
- `-Background` 옵션으로 실행한 경우 스크립트가 안내한 프로세스 번호를 확인하고, 종료는 작업 관리자에서 해당 `node` 프로세스를 대상으로 합니다. 다른 프로그램의 프로세스를 추측해 종료하지 마세요.

## 4. 시스템 구성과 데이터 흐름

```text
사용자 브라우저
  ├─ public/index.html / public/style.css
  ├─ public/app.js — 화면, 사용자 동작, API 요청·상태 관리
  └─ student/extension.mjs — 제공 UI가 호출하는 학생 화면 표시 슬롯
                 │ same-origin HTTP, 127.0.0.1의 로컬 주소
                 ▼
로컬 앱 서버: src/server.mjs
  ├─ 제공 API와 정적 파일을 처리
  ├─ 기본 상태: 기존 엔진 미연결
  ├─ 운영자가 별도 준비한 경우에만 선택적 SDP 연결 경로
  │    └─ src/engine/sdp-host.mjs → student/engine-adapter.mjs → 승인된 SDP/XDR 원천
  ├─ 서버 측 AI 요청·권한 경로
  │    └─ AI 게이트웨이(C L C O / CLCO) → 승인된 AI 서비스
  └─ 설치 패키지 조회 경로
       └─ 운영자가 허용한 공개 npm 패키지 → OSV 공개 취약점 데이터
```

구성 요소의 관계를 정리한 그림이며, 각 선택적 연결이 현재 이 PC에 설정되었거나 운영 권한이 준비되었다는 의미는 아닙니다. 기본 실행은 미연결입니다. `-Demo`는 예제 데이터를 제공합니다. AI 게이트웨이와의 통신은 앱 서버 경로이며 브라우저에서 공급사에 직접 연결하거나 열쇠를 입력하는 구조가 아닙니다. 학생은 Workbench 열쇠나 AI 공급사 원본 열쇠를 복사하지 않습니다.

| 구성 | 파일 또는 경로 | 담당 범위 |
|---|---|---|
| 제공 화면·브라우저 로직 | `public/index.html`, `public/app.js`, `public/vulnerabilities-view.mjs` | 화면 틀, API 요청, 사용자 동작, 상태·취소 처리, 취약점 조회 표시를 제공 |
| 학생 화면 확장 | `student/extension.mjs` | `createStudentView`와 학생 렌더러 슬롯을 제공합니다. 제공 UI가 `renderIdentity`, `renderDecision`, `renderEvents`, `renderStatus`, `renderVulnerabilities`, `renderAiConnection`, `renderExplanation`, `renderAction`을 연결합니다. |
| 로컬 서버·API | `src/server.mjs` | loopback 로컬 서버에서 정적 파일과 API를 제공합니다. 실패는 성공으로 바꾸지 않습니다. |
| 엔진 선택 | `src/engine.mjs`, `student/engine-adapter.mjs` | 기본 미연결 경로와 명시적으로 구성된 엔진 어댑터의 경계를 둡니다. 어댑터가 없는 기능을 빈 성공으로 가장하지 않습니다. |
| AI 서비스 | `src/ai/`, `src/connection/` | 앱 서버 측 AI 서비스와 명시적 연결·권한 경로입니다. 설정 및 운영 권한 준비는 학생 렌더러만으로 대체할 수 없습니다. |
| 패키지·OSV 조회 | `src/vulnerabilities/`, `public/vulnerabilities-view.mjs` | 허용된 공개 패키지의 정확한 설치 버전을 조회하고 조회 실패·미조회·부분 결과를 구분합니다. |
| 실행 도구 | `tools/start-alekov.ps1` | 실행 전 확인, Node 프로세스 시작, 서버 응답 대기 및 실행 안내를 담당합니다. |

학생 확장 API는 제공 UI가 허용한 조회 경로로 제한됩니다. 제공 UI가 학생 함수에 전달하는 값은 해당 렌더러의 현재 상태 스냅샷입니다. 세부 필드 계약은 각 단계 안내와 제출 시점의 실제 소스를 기준으로 확인해야 합니다. 이 설명서만으로 특정 화면 결과나 외부 연결의 성공을 보증하지 않습니다.

|---|---|---|
| 로컬 앱 시작 | PowerShell 실행 도구와 기본 포트·Node.js 확인 경로가 있습니다. | 이번 세션에서는 명령을 실행하지 않았습니다. |
| 기본 모드·예제 모드 | 기본 엔진 경로와 `--demo` 예제 경로가 코드에 구분되어 있습니다. | 실제 서버 화면 및 외부 시스템 연결은 확인하지 않았습니다. |

| 사건 설명·조치 | 화면/API 경로가 별도로 있고, AI 설명과 서버 처리 결과는 별도 상태입니다. | 실제 사건 설명이나 보안 조치 집행은 실행하지 않았습니다. 실제 집행 연결의 준비 여부를 이 실행 문서로 입증하지 않습니다. |
| 패키지 조회 | 서버가 프로젝트 설정과 운영자 승인 목록을 이용하고 OSV 조회 코드가 있습니다. | 실제 lockfile 대조, OSV 네트워크 조회, 취약점 결과는 확인하지 않았습니다. |
| 제출·단계 판정 | 공식 안내상 서버는 제출된 커밋의 원문을 읽어 판정하며 명령을 실행하지 않습니다. | 커밋, 제출, 원문 전달, 서버 판정은 수행하지 않았습니다. |

## 6. 오류가 발생했을 때

먼저 오류가 난 위치를 구분합니다. 아래 복구는 오류에 해당하는 항목만 확인하고, 기존 파일·설정·작업을 삭제하거나 임의로 바꾸지 않는 순서입니다.

| 증상 또는 코드 | 확인 방법 | 복구·다음 조치 |
|---|---|---|
| `Node.js 가 없습니다` | 새 PowerShell에서 `node --version`을 확인합니다. | 수업 기준 Node.js `24.19.0`을 설치한 뒤 새 PowerShell 창에서 다시 확인합니다. |
| 지원 범위 밖 Node.js 버전 | 실행 도구가 표시한 버전과 Node.js 주 버전을 확인합니다. | Node.js 22~24를 사용하고, `24.19.0`을 권장 기준으로 삼습니다. |
| `앱 폴더가 아닙니다` 또는 시작 스크립트·파일 없음 | PowerShell의 현재 위치와 `package.json`, `tools\\start-alekov.ps1`, `src\\server.mjs` 존재를 확인합니다. | 앱 루트(`on-client`)에서 명령을 다시 실행합니다. 다른 폴더를 초기화하거나 파일을 복사해 덮어쓰지 않습니다. |
| 포트가 이미 사용 중 | 실행 도구가 출력한 포트 번호를 확인합니다. | 다른 프로그램을 종료하지 말고 `-Port 5190`처럼 다른 번호를 지정합니다. 브라우저 주소도 그 포트로 맞춥니다. |
| 서버가 제한 시간 안에 응답하지 않음 | 실행 도구가 출력한 포트 번호를 확인합니다. | 경로·Node.js·포트를 다시 확인합니다. 해결되지 않으면 오류 메시지를 담당자에게 전달합니다. 이것을 AI 연결 실패 또는 성공으로 단정하지 않습니다. |
| 앱이 열리지만 `disconnected`, 권한 준비 중, 확인 불가 또는 연결 오류 | 앱 화면의 상태 코드와 비밀이 없는 도움정보를 확인합니다. | 기본 미연결은 가능한 상태입니다. 운영 계정·앱 권한·게이트 설정이 필요한 오류는 담당자에게 확인합니다. 열쇠·토큰을 채팅·화면·문서에 복사하지 않습니다. |
| 패키지 조회 `not_configured`, `not_checked`, `partial`, `unverifiable` 또는 오류 | 전체 조회 상태와 패키지별 상태·정확한 버전·출처·시각을 구분해 확인합니다. | 설정 없음·미조회·확인 불가를 취약점 없음으로 보지 않습니다. 대상 경로와 허용 패키지는 담당자가 준비합니다. 조회를 위해 의존성 버전을 임의로 낮추지 않습니다. |
| 설명 실패 또는 조치 결과 `unknown` | 보안 기록과 화면의 오류·요청 상태를 확인합니다. | 실패나 결과 불명을 성공·효과 없음으로 바꾸지 않습니다. 실제 조치를 시험 삼아 실행하지 말고, 제공 화면의 결과 확인 절차와 담당자 안내를 따릅니다. |

도움정보는 화면에서 내용을 직접 확인한 뒤 필요한 경우에만 공유하세요. 승인 번호, 연결 식별자, 비밀 설정값, 인증서, 토큰, API 키는 이 문서나 제출물에 넣지 않습니다.

## 7. 지원 범위와 미확인 항목

- 이 실행 안내는 Windows PowerShell 실행 스크립트를 기준으로 합니다. 다른 운영체제에서의 `.ps1` 실행은 이 문서에서 지원하거나 확인하지 않았습니다.
- 로컬 서버는 loopback 주소를 사용합니다. 서버 시작만으로 회사의 SDP/XDR 시스템, AI 게이트웨이, 학생 계정 또는 모델 권한이 연결되는 것은 아닙니다.
- 네이티브 계정 연결이나 SDP 연결 설정은 담당자가 실제 사용자·프로젝트에 맞게 별도로 준비한 경우에만 사용합니다. 학생이 설정 견본을 임의로 만들거나 다른 사람 설정을 복사하지 않습니다.
- OSV 조회는 승인된 공개 패키지의 알려진 취약점 정보를 확인하는 절차입니다. 조회 결과가 없다는 사실은 패키지나 앱 전체의 안전을 보장하지 않습니다.
- 이 세션에서 **실제로 실행해 확인한 항목은 없습니다.** 설치된 Node.js 버전, 새 PowerShell에서의 서버 시작, 브라우저 화면, 버튼 이름, 실제 연결, OSV 결과, 실제 조치, Git 상태는 모두 미확인입니다.

## 8. 21·22단계 커밋과 원문 제출

1. 기존 작업을 먼저 확인하고, 학생 문서와 이번 단계 코드를 같은 커밋에 저장합니다. 커밋 해시를 문서에 임의로 기재하지 않습니다.
2. 21·22단계는 과제 화면에 저장소 주소와 제출할 40자리 커밋을 직접 입력합니다. 현재 워크벤치의 「포털 제출 준비」는 13~20단계용이므로 21·22단계에 해당 버튼이 있다고 가정하지 않습니다.
3. 비공개 저장소라면 과제 화면의 「비공개 저장소 원문 준비 방법」을 열고 「원문 전달 도구 받기」를 사용합니다. ZIP과 출력 JSON 폴더는 프로젝트 밖에 준비합니다.
4. 구체적인 `student-source-cli.mjs` 명령은 과제 화면에 표시된 명령을 사용합니다. 도구와 출력 파일 경로는 본인 PC에서 확인한 경로로 바꾸고, `--commit`에는 제출할 실제 커밋을 지정해야 합니다. 이 세션에서는 로컬 절대 경로, Git 최상위 폴더, 커밋 해시, 화면에 제공된 도구 명령을 확인하지 않았으므로 명령을 만들어 적지 않았습니다.
5. 생성한 JSON을 같은 단계의 「비공개 저장소 원문 묶음」에서 선택하고 저장소·커밋·단계를 확인한 뒤 제출합니다. 원문 전달 완료는 AI 검토 통과와 다릅니다. 서버 상태와 판정 설명을 각각 확인합니다. 원문 전달만 실패한 경우에는 기존 접수를 보존하고 화면의 「원문만 다시 보내기」 절차를 따릅니다.

원문 전달 도구는 안내에 따라 커밋된 원문을 묶는 용도이며 학생 코드를 실행하거나 업로드하는 절차가 아닙니다. 실제 도구 명령과 경로는 과제 화면 및 본인 저장소 상태를 확인한 뒤 결정하세요.
