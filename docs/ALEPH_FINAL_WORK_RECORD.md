### 핵심 기능 2: 내 PC 보안·네트워크 구성 실측 현황판 및 다중 어댑터 아코디언 토글
- **기능 이름**: 내 PC 보안·네트워크 구성 실측 현황판 및 네트워크 토글
- **제공된 부분**: 없음 (기존 시작 틀에는 로컬 PC 실측 기능이 부재했음)
- **내가 직접 개선한 부분**:
  - 백엔드 실측 엔드포인트(`GET /api/system-security`) 신설:
    - 활성 IPv4 주소 및 서브넷 마스크 실측 (`node:os` 모듈의 `os.networkInterfaces()`)
    - Windows 방화벽 도메인·개인·공용 프로필 상태 읽기 전용 점검 (`netsh.exe advfirewall show allprofiles state`)
    - 최근 24시간 Windows 이벤트 로그 오류·경고 건수 비동기 집계 (`Get-WinEvent` 필터 활용)
  - 프론트엔드 다중 어댑터 접기/펼치기(Accordion) 토글: 주 어댑터 기본 표시 + `[+N개 어댑터 보기]` 토글 지원
  - 필수 보안 안내 문구 추가: *"안내: 아래 이벤트 기록 건수는 침해나 공격 탐지 결과가 아닙니다. 일반 Windows 시스템 및 응용 프로그램 동작 중 기록된 정상적인 경고·오류입니다."*
- **실제 확인 결과**: 정상 작동 확인 (이더넷 IPv4 `192.168.4.5`, 보조 가상 어댑터 2개, 방화벽 도메인/개인/공용 모두 '사용 중 (보호됨)', System 25건, Application 9건 실측 렌더링 확인)
- **잘못된 입력이나 연결 실패 때의 동작**: 방화벽 또는 이벤트 로그 권한 부족이나 서비스 미응답 시 가짜 정상 값을 만들지 않고 '확인 불가' 및 구체적 원인(권한 필요) 명시
- **근거(개인정보를 지운 화면, 실행 기록, 상대 경로)**:
  - 상대 경로: `src/server.mjs`, `student/extension.mjs`
  - 실행 기록: `powershell -File .\dist\Keshev\tools\start-alekov.ps1 -Demo` 실행 후 화면 실측치 출력 확인

### 핵심 기능 3: 실시간 비동기 [다시 조회] (대기 표시·Delta 추이 뱃지·원클릭 리포트 복사)
- **기능 이름**: 실시간 비동기 다시 조회 및 실측 인터랙션
- **제공된 부분**: 전체 페이지 새로고침(F5) 방식
- **내가 직접 개선한 부분**:
  - 부분 비동기 재조회 버튼(`[다시 조회]`) 신설 및 대기 표시(`⏳ 로컬 PC 보안 상태를 측정하는 중입니다…` 로딩 인디케이터)
  - **직전 대비 변동 추이(Delta) 컬러 뱃지**: 이전 측정값 대비 System 오류 건수(`±0건` 또는 `+N건`), Application 오류, RAM 사용률 변화량(`%p`) 실시간 계산 및 뱃지 표시
  - **원클릭 `[📋 리포트 복사]`**: 헤더 복사 버튼을 눌러 측정 시각, IP, 방화벽, 이벤트 오류, 메모리 실측 데이터를 증빙 텍스트로 즉시 클립보드 복사 (`✓ 복사 완료!` 피드백)
  - **W3C 접근성 준수**: `tabindex="0"`, `aria-label`, 키보드 `Enter`/`Space` 이벤트 바인딩으로 마우스 없이 키보드만으로 완벽 제어 가능
  - 조회 실패 시 안전 안내 배너(`sec-error-guidance`): 실패 항목과 다음에 할 일을 명확히 제시
- **실제 확인 결과**: 정상 작동 확인 (버튼 클릭 시 로딩 인디케이터 노출 후 `System: ±0건`, `RAM: -0.1%p` 등 실시간 Delta 뱃지 생성, 복사 버튼 동작 검증)
- **잘못된 입력이나 연결 실패 때의 동작**: 서버 통신 실패 시 가짜 예시값을 절대 출력하지 않고 실패한 항목(API 엔드포인트)과 다음에 할 일(서버 실행 확인 등)을 배너로 안내
- **근거(개인정보를 지운 화면, 실행 기록, 상대 경로)**:
  - 상대 경로: `student/extension.mjs`, `public/style.css`
  - 실행 기록: `npm run check` 통과, 키보드 Tab 및 Enter 인터랙션, 클립보드 복사 텍스트 검증 완료

## 3. 값의 종류 구분 (정직한 데이터 명세)

화면에 표시되는 모든 데이터는 아래 4가지 범주로 엄격히 분리되어 관리됩니다:

1. **실제 조회 (내 PC 실측 및 시스템 API 결과와 출처·조회 시각)**:
   - 로컬 네트워크 IPv4 주소 (`os.networkInterfaces()`, 일반 권한)
   - Windows 방화벽 읽기 전용 점검 상태 (도메인/개인/공용 모두 '사용 중 (보호됨)', `netsh advfirewall`)
   - 최근 24시간 Windows 이벤트 로그 (System 오류·경고 25건, Application 오류·경고 9건, `Get-WinEvent`)
   - 실시간 시스템 RAM 사용률 (53.5%, 총 16.0 GB 중 8.5 GB 사용, `node:os`)
   - 각 측정 항목마다 잰 시각(예: 10:01:16)과 단위를 명시
2. **설명용 예시 (실제 조회 결과가 아닌 학습용 모의 데이터)**:
   - SDP 기기 준수 상태 (`보안 기준 충족(compliant) · 연습 PC`)
   - 로그인 세션 (`활성(active) · practice-session`)
   - 실시간 위협 및 조치 (`위협 1건 탐지 (모의) · 조치 대기: 0건`)
3. **미연결 (외부 서버에 연결되지 않은 항목)**:
   - SDP 서버 실제 연결: `[SDP 미연결] (PC 로컬 실측 성공 데이터와 독립적으로 분리됨)`
4. **확인 불가 (읽지 못한 값과 그 이유)**:
   - 관리자 권한이 필요한 레지스트리 심층 보안 설정 (비파괴 안전 원칙에 따라 임의 변경 없이 '확인 불가' 유지)
   - 중앙 AI 게이트웨이 및 계정 연결 (`NATIVE_HOST_DISABLED`, 운영자 전용 native.json 설정 파일 미발급 상태)

## 5. 처음 사용한 사람이 막힌 곳과 보완 내역

- **다른 사람의 첫 사용 관찰 여부**: 확인 완료
- **막힌 위치 및 원인 분석**:
  1. `케셰브 시작.lnk` (바로가기) 클릭 시 검은 창이 켜졌다가 바로 꺼진 현상:
     - 원인: Windows 바로가기 파일 특성상 빌드 당시의 절대 경로(`AppData\Local\ALEPH...`)가 기록되어, 다른 폴더나 PC로 이동 시 대상을 찾지 못함
  2. 서버 재기동 시 `EADDRINUSE: address already in use 127.0.0.1:5189` 오류 발생:
     - 원인: 이전 실행 프로세스(node.exe)가 백그라운드에 남아 포트를 선점함
  3. `-NativeHostConfig` 옵션을 임의 경로로 넣어 실행했을 때 `파일이나 상위 경로를 확인하지 못했습니다` 오류 발생:
     - 원인: 학생 검수 모드에서는 `-Demo` 플래그만 넣어야 하는데 운영자용 파라미터가 잘못 안내됨
- **내가 보완한 것**:
  1. 상대 경로(`%~dp0`)를 사용하여 어디서나 실행 가능한 `dist\Keshev\케셰브 시작.bat` 실행을 기본으로 표준화하고, 바로가기 타겟 경로도 현재 실제 바탕화면 경로로 전면 수정
  2. 포트 충돌 시 대응 안내(`-Port 5190` 옵션 활용) 문서화
  3. 처음 보는 사람용 퀵스타트 가이드에 `-Demo` 플래그 단일 명령어로 명확히 정리
- **다른 사람이 보완 뒤 다시 따라 해 본 결과**: 100% 정상 실행 확인 (배치 파일 더블클릭만으로 오류 없이 관제 대시보드 오픈)
